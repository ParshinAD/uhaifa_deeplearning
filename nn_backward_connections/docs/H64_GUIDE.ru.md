## 1. Задача и как мы её измеряем

**Дано:** ориентированный взвешенный граф. Для мухи (FlyWire) это 136 648 нейронов и
5 657 719 рёбер «нейрон → нейрон», вес ребра = число синапсов. Суммарный вес 41 912 141.

**Нужно:** расставить все нейроны на одной прямой (задать перестановку π) так, чтобы как можно
больший суммарный вес рёбер шёл «вперёд», то есть от более раннего узла к более позднему.

Формально. Пусть `rank[u]` — позиция узла `u` (0 — самый первый). Ребро `(u → v)` с весом `w`
называется **feedforward**, если `rank[u] < rank[v]`, иначе это **feedback** (обратная связь).

```
S(rank) = Σ_{(u→v)}  w_uv · [ rank[u] < rank[v] ]          (максимизируем)
feedback-вес = W_total − S(rank)                            (минимизируем — то же самое)
```

Это задача **Maximum Feedforward Arc Set** (эквивалентно минимальному Feedback Arc Set), она
NP-трудна. Мы говорим о качестве в процентах: `S / W_total · 100`.

**Оракул.** Единственная «правда» о качестве порядка — функция `score_from_order` в
`src/mfas/metrics.py`. Она заморожена. Три правила, которые нельзя нарушать:

1. веса суммируются в int64 (муха) / float64 (мышь), никогда во float32 — иначе на 5.7 млн рёбер
   теряются единицы (исторический баг 34 751 904 против верных 34 751 902);
2. считать всегда на CPU (индексные операции на MPS во float32 иногда возвращают мусор);
3. ни один алгоритм не смотрит в оракул, чтобы **выбрать ход**. Оракул только принимает или
   отвергает целый готовый вектор порядка («best-by-oracle»). Это защита от утечки метрики.

Минимальный код оракула (побитово совпадает с продакшном, проверено):

```python
def score(rank, src, tgt, w):
    w = np.asarray(w)
    w = w.astype(np.int64) if np.issubdtype(w.dtype, np.integer) else w.astype(np.float64)
    ff = rank[tgt] > rank[src]          # строго: равенство считается feedback
    return float(w[ff].sum())
```

`rank` может быть и целой перестановкой, и вещественным вектором позиций — проверка
`rank[tgt] > rank[src]` одинакова.

## 3. Стадия 1 — жадный стартовый порядок (greedy-FAS)

### 3.1 Идея

Rocket (стадия 2) — градиентный спуск, ему нужна стартовая точка. В статье старт случайный
N(0, 1). Мы стартуем с дешёвого жадного порядка, который уже даёт ~69% feedforward. Это
классический приём «continuation»: непрерывный оптимизатор начинает рядом с хорошим дискретным
решением.

Алгоритм — эвристика Eades–Lin–Smyth (1993) для FAS. В терминах статьи Bader et al. это
**«Greedy»** (одностороннее правило «max(out_w − in_w) → в начало»; у статьи 69.25%, у нас
68.91%), а не «GreedyAbs» (двустороннее правило по |out_w − in_w|, 73.12%). Докстринг `H02.py`
называет её GreedyAbs — это неточность ярлыка, сам код и число соответствуют Greedy. Мы
последовательно «сдираем» узлы с графа:

* узел без оставшегося **исходящего** веса — это сток (sink): кладём его в **конец** линии;
* узел без оставшегося **входящего** веса — это источник (source): кладём в **начало**;
* если ни того ни другого нет, берём узел с максимальной разностью `out_w − in_w`
  («самый источникоподобный») и кладём в начало.

Когда узел удалён, его рёбра вычитаются из оставшихся степеней соседей, и соседи могут стать
стоками/источниками. На ациклическом графе это ровно топологическая сортировка; на графе с
циклами (оба коннектома) — стандартный жадный суррогат.

Почему не наивно: наивный «argmax по всем узлам на каждом шаге» — O(n²) ≈ 1.8·10¹⁰ операций на
136k узлах. Поэтому ленивая max-куча: в кучу кладём `(-(out_w − in_w), u)`, а при извлечении
пропускаем устаревшие записи (значение не совпадает с текущим `heap_val[u]`). Итого
O((n + m) log n), 18 секунд на мухе.

### 3.2 Код

```python
def greedy_fas_order(n, src, tgt, w):
    src = src.astype(np.int64); tgt = tgt.astype(np.int64); w = w.astype(np.float64)
    out_w = np.zeros(n); in_w = np.zeros(n)
    np.add.at(out_w, src, w); np.add.at(in_w, tgt, w)

    # CSR-смежность: исходящие рёбра u и входящие рёбра v — для O(deg) обновлений
    o = np.argsort(src, kind="stable"); out_start = np.searchsorted(src[o], np.arange(n + 1))
    out_nbr, out_wt = tgt[o], w[o]
    i = np.argsort(tgt, kind="stable"); in_start = np.searchsorted(tgt[i], np.arange(n + 1))
    in_nbr, in_wt = src[i], w[i]

    EPS = 1e-12
    active = np.ones(n, dtype=bool)
    rank = np.empty(n, dtype=np.int64)
    front, back = 0, n - 1
    sinks   = [u for u in range(n) if out_w[u] <= EPS]
    sources = [u for u in range(n) if in_w[u] <= EPS and out_w[u] > EPS]
    heap = [(-(out_w[u] - in_w[u]), u) for u in range(n) if out_w[u] > EPS and in_w[u] > EPS]
    heapq.heapify(heap)
    heap_val = (out_w - in_w).copy()     # запись в куче валидна, только если совпадает с этим

    def remove(u, to_front):
        nonlocal front, back
        active[u] = False
        if to_front: rank[u] = front; front += 1
        else:        rank[u] = back;  back -= 1
        for k in range(out_start[u], out_start[u + 1]):       # u -> v: v теряет входящий вес
            v = int(out_nbr[k])
            if active[v]:
                in_w[v] -= out_wt[k]
                if in_w[v] <= EPS and out_w[v] > EPS: sources.append(v)
                else:
                    heap_val[v] = out_w[v] - in_w[v]; heapq.heappush(heap, (-heap_val[v], v))
        for k in range(in_start[u], in_start[u + 1]):         # x -> u: x теряет исходящий вес
            x = int(in_nbr[k])
            if active[x]:
                out_w[x] -= in_wt[k]
                if out_w[x] <= EPS: sinks.append(x)
                else:
                    heap_val[x] = out_w[x] - in_w[x]; heapq.heappush(heap, (-heap_val[x], x))

    placed = 0
    while placed < n:
        progressed = False
        while sinks:
            u = sinks.pop()
            if active[u] and out_w[u] <= EPS:
                remove(u, False); placed += 1; progressed = True
        while sources:
            u = sources.pop()
            if active[u] and in_w[u] <= EPS and out_w[u] > EPS:
                remove(u, True); placed += 1; progressed = True
        if placed >= n: break
        if progressed: continue
        u = -1
        while heap:                                   # вынимаем, пока не найдём актуальную запись
            neg, cand = heapq.heappop(heap)
            if active[cand] and -neg == heap_val[cand]:
                u = cand; break
        if u == -1:                                   # численный запасной путь, на практике не срабатывает
            rem = np.nonzero(active)[0]
            u = int(rem[int(np.argmax(out_w[rem] - in_w[rem]))])
        remove(u, True); placed += 1
    return rank
```

Ранги переводятся в равномерные позиции на отрезке [−1, 1] (ранг 0 → −1, ранг n−1 → +1), потому
что Rocket работает с вещественными координатами и соглашение «feedforward ⇔ pos[u] < pos[v]»
должно сохраниться:

```python
def positions_from_rank(rank):
    n = rank.shape[0]
    return ((rank.astype(np.float32) / max(n - 1, 1)) * 2.0 - 1.0).astype(np.float32)
```

## 4. Стадия 2 — Rocket с асимметричным суррогатом

### 4.1 Идея Rocket (Bader et al. 2025, Algorithm 1)

Перестановка — дискретный объект, градиента у неё нет. Rocket делает **непрерывную релаксацию**:
каждому узлу даётся вещественная координата `p[u]`, и вместо индикатора `[p[u] < p[v]]` берётся
гладкая функция разности `Δ = p[v] − p[u]`:

```
F(p) = Σ_e  ŵ_e · σ(β · Δ_e),      ŵ_e = w_e / max(w),   σ — сигмоида,   loss = −F
```

`β` — «резкость»: при большом β сигмоида приближается к ступеньке (индикатору), при малом —
сглаживает ландшафт. Статья меняет β циклически по косинусу (5 периодов, β ∈ [0.05, 1.05]):
периоды «размягчения» помогают выбираться из локальных максимумов. Оптимизатор Adam, lr = 0.05
первую половину эпох, затем экспоненциальное убывание до 0.005, клиппинг нормы градиента 1.0.
20 000 эпох на мухе.

Каждые 100 эпох текущие позиции скорятся оракулом (на CPU, точно), и лучший вектор запоминается
(best-by-oracle). Возвращается именно он, а не последние позиции.

### 4.2 Что меняет H64: форма суррогата

На мухе единственное изменение относительно чемпиона H42 — одна строка: вместо
`torch.sigmoid(β·Δ)` используется односторонний асимметричный суррогат из варианта H38
(для мыши модуль H64 дополнительно наследует константы мышиного чемпиона H63, см. §7):

```
g(z) = 1                          при z ≥ M
g(z) = 1 + tanh((z − M) / T)      при z <  M          z = β·Δ,   (M, T) = (0.75, 1.5)
```

Смысл. Сигмоида симметрична: ребро, которое уже «уверенно feedforward» (Δ ≫ 0), всё ещё даёт
градиент и тянет свои концы дальше друг от друга — тратит бюджет на расширение уже правильного
зазора. Функция `g` **плоская** при `z ≥ M`: правильные с запасом рёбра дают нулевой градиент, и
весь градиент идёт на нарушенные и пограничные рёбра. Свойства: монотонно неубывает по Δ
(значит, argmax по-прежнему «максимизируй feedforward»), ограничена в (0, 1], непрерывна в
`z = M` (излом производной там есть, это задокументировано).

Почему нужен запас `M > 0`. При `M = 0` имеем `g(0) = 1`, и конфигурация «все узлы в одной
точке» (`p = const`) достигает `F = Σ ŵ_e` — глобального максимума суррогата, строго выше любого
порядка. Динамика туда и сваливается: проверено на синтетике — коллапс до std позиций 0.0005 и
58.24% против 73.68% у сигмоиды. При `M > 0` `g(0) < 1`, коллапс перестаёт быть оптимальным.

Откуда `(M, T) = (0.75, 1.5)`. Сетка 6×3 на **мыши и синтетическом графе** (не на мухе):
единственная точка, положительная на обоих прокси. Оптимум зависит от графа, это заявлено
честно (`H38.py`, докстринг).

Что это дало на мухе. Чистый Rocket: 82.9297% → 83.2379% (+0.308 п.п.) при том же бюджете
градиентных шагов, той же инициализации и тех же расписаниях.

Контроли формы — с оговоркой о происхождении. В исходном эксперименте H38 (чистый Rocket,
**случайный старт N(0,1), Apple MPS, сравнение с базовой линией 82.896%**, а не с чемпионом)
зеркальная форма (плоская со стороны feedback, H38C) дала −2.89 п.п., а обычная сигмоида с
β×4 (H38D) −0.58 п.п. при +0.367 у самой ASYM. Это говорит, что в той постановке выигрывало
именно **направление** асимметрии, а не масштаб β. В составе конвейера H64 (тёплый старт,
CUDA, сравнение с чемпионом) эти контроли **не повторялись**: H64 измерял только саму ASYM
против сигмоиды. Руководителю это стоит сказать прямо.

### 4.3 Код

```python
def asym_surrogate(z, M, T):
    below = 1.0 + torch.tanh((z - M) / T)
    return torch.where(z >= M, torch.ones_like(z), below)

def beta_schedule(epochs, cycles):
    return (np.cos(np.linspace(0, 2 * cycles * np.pi, epochs)) + 1.1) / 2   # [0.05, 1.05]

def rocket_asym(n, src, tgt, w, init_pos, cfg, seed, device, verbose=True):
    torch.manual_seed(seed); np.random.seed(seed)          # seed фактически не используется
    src_t = torch.tensor(src, dtype=torch.long, device=device)
    tgt_t = torch.tensor(tgt, dtype=torch.long, device=device)
    w_hat = torch.tensor((w / w.max()).astype(np.float32), device=device)

    positions = torch.nn.Parameter(torch.tensor(init_pos, dtype=torch.float32, device=device))
    opt = torch.optim.Adam([positions], lr=cfg["lr"])
    E = cfg["epochs"]
    milestone = int(E * cfg["lr_decay_start"])                              # 10 000
    gamma = cfg["lr_end_factor"] ** (1.0 / max(E - milestone, 1))           # 0.1^(1/10000)
    sched = torch.optim.lr_scheduler.SequentialLR(
        opt,
        [torch.optim.lr_scheduler.ConstantLR(opt, factor=1.0, total_iters=milestone),
         torch.optim.lr_scheduler.ExponentialLR(opt, gamma=gamma)],
        milestones=[milestone])
    betas = beta_schedule(E, cfg["beta_cycles"])

    def exact(p):                                   # оракул, всегда на CPU
        return score(p.detach().cpu().numpy(), src, tgt, w)

    best_score = exact(positions); best_pos = positions.detach().clone()
    for i in range(E):
        beta = float(betas[i])
        opt.zero_grad()
        delta = positions[tgt_t] - positions[src_t]                  # > 0  <=> feedforward
        loss = -(asym_surrogate(beta * delta, cfg["asym_M"], cfg["asym_T"]) * w_hat).sum()
        loss.backward()
        torch.nn.utils.clip_grad_norm_([positions], cfg["grad_clip"])
        opt.step(); sched.step()
        if i % cfg["log_interval"] == 0 or i == E - 1:
            s = exact(positions)
            if s > best_score:
                best_score, best_pos = s, positions.detach().clone()
    return best_pos.cpu().numpy(), best_score
```

Константы стадии 2 (все из `CONFIG` в `h64_minimal.py`, совпадают с `RocketConfig` и `H64.py`):

### 4.4 Как объяснить руководителю

«Rocket — непрерывная релаксация: узлам даём координаты, индикатор заменяем гладкой функцией и
делаем Adam по координатам, с циклическим отжигом резкости β. Мы поменяли только форму гладкой
функции: сделали её плоской для рёбер, которые уже правильно ориентированы с запасом. Тогда
градиент не тратится на расширение уже правильных зазоров, а целиком идёт на обратные связи.
Один этот шаг дал +0.31 п.п. чистого Rocket и +0.10 п.п. после всей дискретной доработки, при
том же числе градиентных шагов и на 47 с быстрее».

## 5. Стадия 3 — точный sift с недорелаксацией

### 5.1 Задача одного узла: куда его вставить

После Rocket у нас вещественные позиции; переводим их в ранги (stable argsort дважды). Теперь
чисто дискретный локальный поиск. Базовый ход: **вынуть один узел `u` и вставить его в лучшее
место**, остальные не трогая. Замечательное свойство: для одного узла лучшее место находится
**точно**, и профиль зависит только от deg(u) инцидентных рёбер. Учебный код ниже строит
профиль разностным массивом длины n, то есть стоит O(n) на узел и O(n²) на проход — на мыши
это мгновенно, на мухе неприемлемо. Продакшн-ядро (§5.1, конец) делает то же за
O(m log m) на весь проход.

Вынимаем `u` с позиции `p`. Остальные узлы сохраняют порядок и получают «сокращённые ранги»:
`q(x) = rank[x]` если `rank[x] < p`, иначе `rank[x] − 1`. Возможных мест для вставки n штук —
«щели» (gap) `g = 0 … n−1` (`g = 0` — перед всеми, `g = n−1` — после всех).

Вклад рёбер узла `u` как функция от `g`:

* исходящее ребро `u → v` feedforward ⇔ `u` раньше `v` ⇔ `g ≤ q(v)`: даёт `+w` на `g ∈ [0, q(v)]`;
* входящее ребро `x → u` feedforward ⇔ `u` позже `x` ⇔ `g > q(x)`: даёт `+w` на `g ∈ [q(x)+1, n−1]`.

Значит, `total_u(g)` — кусочно-постоянная функция с не более чем deg(u) точками излома. Строим её
разностным массивом и берём argmax. Рёбра, не инцидентные `u`, от хода не зависят, поэтому
`gain = total_u(g*) − total_u(p)` — **точный** прирост оракула от одиночного хода. Петли `u → u`
не меняются ни при каком ходе и отбрасываются.

Маленький пример. Узлы A, B, C, D в порядке [A, B, C, D], рёбра B→A (вес 5), A→C (вес 1).
Вынимаем A (p = 0): сокращённые ранги B = 0, C = 1, D = 2. Профиль по щелям g = 0..3:
исходящее A→C даёт +1 на g ∈ [0, 1]; входящее B→A даёт +5 на g ∈ [1, 3].
total = [1, 6, 5, 5], argmax = 1 → вставить A после B: порядок [B, A, C, D], gain = 6 − 1 = 5.

Тай-брейк: при плато максимума берём **наименьшую** щель (`tie_break="first"`). Это правило
закреплено тестом, потому что чемпион измерен именно с ним (вариант H73 пробовал «ближайшую щель»
и проиграл).

```python
def best_gap_for_node(u, rank, adj):
    n = adj["n"]; p = int(rank[u])
    D = np.zeros(n + 1)
    for k in range(adj["out_start"][u], adj["out_start"][u + 1]):
        v = int(adj["out_nbr"][k]); qv = rank[v] if rank[v] < p else rank[v] - 1
        D[0] += adj["out_w"][k]; D[qv + 1] -= adj["out_w"][k]     # +w на g in [0, qv]
    for k in range(adj["in_start"][u], adj["in_start"][u + 1]):
        x = int(adj["in_nbr"][k]); qx = rank[x] if rank[x] < p else rank[x] - 1
        D[qx + 1] += adj["in_w"][k]                                # +w на g in [qx+1, n-1]
    total = np.cumsum(D[:n])
    g = int(np.argmax(total))                                      # первый максимум
    return g, float(total[g] - total[p])
```

Продакшн-версия (`insertion.py`, `jacobi_best_gaps`) делает то же самое **для всех узлов сразу**
без Python-цикла: одно событие на каждое инцидентное ребро `(u, b = q+1, ±w)`, одна сортировка по
ключу `u·(n+2) + b`, агрегация дельт по одинаковым `(u, b)` (обязательно до взятия максимума),
сегментный cumsum и сегментный максимум. Совпадение с наивной версией проверено брутфорсом в
`tests/test_refine_insertion.py` и в `docs/h64_minimal_check.py`.

### 5.2 Якоби vs Гаусс–Зейдель, и зачем недорелаксация

Двигать узлы можно по одному (Гаусс–Зейдель: пересчитывать после каждого хода) или все сразу по
одному и тому же зафиксированному порядку (Якоби). Якоби векторизуется и на мухе занимает
~3 с за проход, поэтому используется он. Пересборка порядка после прохода: каждому узлу ключ
сортировки, «неподвижным» — их текущий ранг, «движущимся» — `best_gap − 0.5` (чтобы встать в щель
между целыми рангами); новый ранг = двойной stable argsort ключей.

Проблема: чистый Якоби на плотных больших графах **не сходится** — впадает в цикл периода 2,
тысячи узлов перепрыгивают друг через друга бесконечно (диагностика: ~5 255 «движущихся» узлов,
кандидат колеблется 83.807 / 83.796). Лекарство из численных методов — **недорелаксация**:
двигать узел не до цели, а на долю α пути:

```
key[u] = rank[u] + α · ((best_gap[u] − 0.5) − rank[u])        α = 0.7
```

При α = 1 это ровно чистый Якоби (тест `test_alpha1_matches_jacobi_sift_*`). Двухфазное
расписание: первые `k_full = 6` проходов α = 1 (быстрый прогресс, и на маленьких графах Якоби
сам сходится к чуть лучшему оптимуму), потом α = 0.7 (гасит цикл). Рабочий порядок продвигается
безусловно каждый проход, а отдельно ведётся best-by-oracle: возвращается лучший вектор из всех
увиденных, поэтому результат никогда не хуже входа. Остановка: 40 проходов, либо ни один узел не
хочет двигаться (истинная неподвижная точка), либо кончился лимит времени.

Что реально происходит на мухе (seed 42, из `sift_log` прогона): проход 0 — 40 501 движущихся,
83.43%; проход 5 (последний с α = 1) — 21 102, 83.83%; проход 7 — 14 363, 83.93%; лучший
кандидат 84.1176% принят на проходе 36; проход 39 — 164 движущихся, кандидат 84.1176%
(чуть ниже лучшего, отвергнут). Неподвижной точки за 40 проходов не достигли, но плато выйдено.

```python
def sift_underrelaxed(n, src, tgt, w, rank0, *, max_sweeps, k_full, alpha, verbose=True):
    adj = build_adj(n, src, tgt, w)                       # CSR без петель
    work = rank0.astype(np.int64).copy()
    best_rank, best_score = work.copy(), score(work, src, tgt, w)
    for s in range(max_sweeps):
        a = 1.0 if s < k_full else alpha
        gaps = np.empty(n, dtype=np.int64); gain = np.empty(n)
        for u in range(n):                                # в продакшне — векторизовано
            gaps[u], gain[u] = best_gap_for_node(u, work, adj)
        movers = gain > 1e-9
        key = work.astype(np.float64)
        key[movers] = work[movers] + a * ((gaps[movers] - 0.5) - work[movers])
        cand = np.argsort(np.argsort(key, kind="stable"), kind="stable").astype(np.int64)
        cs = score(cand, src, tgt, w)
        work = cand                                       # рабочий порядок идёт дальше всегда
        if cs > best_score:                               # best-by-oracle
            best_rank, best_score = cand.copy(), cs
        if not movers.any():
            break
    return best_rank, best_score
```

### 5.3 Как объяснить руководителю

«После непрерывной фазы делаем точный дискретный локальный поиск: для каждого узла за O(deg)
находим место на линии, максимизирующее его собственный вклад, — это замкнутая формула, не
эвристика. Все узлы двигаем одновременно (итерация Якоби, векторизуется). Чистый Якоби на
большом графе зацикливается с периодом 2, поэтому применяем недорелаксацию с α = 0.7 —
стандартное средство от 2-циклов. Стадия даёт +0.88 п.п. и не может ухудшить вход, потому что
оракул принимает только строго лучшие векторы».

## 6. Стадия 4 — блочное SCC-уточнение, чередуемое с коротким sift

### 6.1 Почему нужен другой класс ходов

Sift двигает по одному узлу. Он слеп к перестановкам, которые выгодны только **совместно**
(каждый узел по отдельности двигать невыгодно, а группу целиком — выгодно). Эксперименты с
«окнами по рангу» (переставлять узлы в пределах ±k позиций) ничего не дали: восстанавливаемый
вес — дальнодействующий. Нужна **структурная** окрестность, а не ранговая. Ею стали сильно
связные компоненты (SCC).

### 6.2 Лемма о непрерывном блоке и монотонность

**Лемма.** Если множество узлов занимает непрерывный отрезок позиций `[lo, hi)`, то любая
перестановка этих узлов **между собой** не меняет ориентацию ни одного ребра с концом вне
отрезка: внешний конец либо раньше всего отрезка, либо позже всего отрезка. Значит, каждый
непрерывный блок — независимая подзадача.

**Ход** для блока B с индуцированным подграфом G[B]:

1. разложить G[B] на сильно связные компоненты;
2. выложить компоненты в топологическом порядке конденсации (это DAG); при равенстве — по
   текущей минимальной позиции компоненты, чтобы уйти от текущего решения минимально;
3. внутри каждой компоненты сохранить текущий относительный порядок узлов; рекурсивно зайти в
   каждую компоненту.

**Почему это монотонно.** Между двумя разными SCC все рёбра идут в одну сторону (ребро назад
слило бы их в одну компоненту), поэтому топологическая выкладка делает **все** меж-компонентные
рёбра feedforward. Внутри компонент порядок не тронут. Итого вклад блока не убывает, и весь
проход не убывает по точному score по построению — accept/reject внутри не нужен (тесты
`test_repeated_passes_are_monotone`, `test_top_level_inter_scc_edges_all_feedforward`).

**Рекурсия.** Блок, который сам — одна SCC, разложить нельзя. Его режем по позиции в точке
`split_frac` и заходим в обе половины: строгий подграф обычно уже не сильно связен и
раскладывается. Доля разреза меняется по циклам: (0.5, 0.382, 0.618, 0.25, 0.75) — граница,
поставленная в другом месте, открывает разложения, невидимые предыдущему разрезу (ребро,
перерезанное границей, не видно ни одной из половин). Это детерминированный список, не
случайность. Блоки размером ≤ 32 не трогаем (вызов scipy дороже, чем возможный выигрыш).

Почему одного верхнеуровневого разложения мало: на мухе верхняя конденсация даёт 9 626 SCC, но
одна гигантская содержит 92.82% узлов; меж-компонентный вес всего 1.50% и уже на 99.99%
feedforward. Выигрыш от верхнего уровня +0.00013 п.п. — ничего. Весь остаток внутри гигантской
компоненты, и рекурсия атакует именно его.

### 6.3 Чередование

Два класса ходов не пересекаются: sift двигает узел относительно своей компоненты, блочный ход
двигает компоненты целиком, но никогда узел внутри компоненты. Каждый открывает ходы, которые
другой исчерпал. Один цикл стадии 4 = один блочный проход + **короткий** sift (2 прохода,
k_full = 2, α = 0.7). Почему короткий: в предыдущей конфигурации H36 (8 проходов sift за цикл)
sift занимал ~88% стоимости цикла (23 с против 3 с на блоки); в текущей, с 2 проходами, это
~5.9 с против ~2.1–2.8 с (около 70%, из `alt_log` прогона H64). При фиксированных 1200 с
143 цикла по 2 прохода дают 84.159 против 84.133 у 47 циклов по 8; это и есть переход от H36 к
H42. Число циклов 77 выбрано по насыщению кривой: к 140-му циклу приращения падают до
~0.00002 п.п./цикл, а полный хвост до 143 циклов добавил бы лишь +0.0047 п.п. за +555 с —
меньше минимального эффекта 0.012 п.п., который кампания считает различием.

На мухе (seed 42, `alt_log`): цикл 0 — после блоков 84.1296, после sift 84.1471; цикл 4 — 84.2032;
цикл 76 — 84.2582. Итого +0.141 п.п. за 632 с.

### 6.4 Код

```python
def topo_order(n_lab, ls, lt, key):
    """Топологический порядок Кана для DAG конденсации; при равенстве — меньший key."""
    if ls.size:
        pair = np.unique(ls.astype(np.int64) * n_lab + lt.astype(np.int64))   # дедупликация
        us, vs = pair // n_lab, pair % n_lab
    else:
        us = vs = np.empty(0, dtype=np.int64)
    indeg = np.zeros(n_lab, dtype=np.int64); np.add.at(indeg, vs, 1)
    o = np.argsort(us, kind="stable"); us, vs = us[o], vs[o]
    start = np.searchsorted(us, np.arange(n_lab + 1))
    heap = [(float(key[i]), int(i)) for i in np.flatnonzero(indeg == 0)]
    heapq.heapify(heap)
    out = []
    while heap:
        _, u = heapq.heappop(heap); out.append(u)
        for j in range(start[u], start[u + 1]):
            v = int(vs[j]); indeg[v] -= 1
            if indeg[v] == 0:
                heapq.heappush(heap, (float(key[v]), v))
    assert len(out) == n_lab, "condensation must be a DAG"
    return np.asarray(out, dtype=np.int64)


def scc_refine(n, src, tgt, rank, *, min_block, split_frac):
    keep = src != tgt
    src, tgt = src[keep].astype(np.int64), tgt[keep].astype(np.int64)
    pos = rank.astype(np.int64).copy()
    seq = np.empty(n, dtype=np.int64); seq[pos] = np.arange(n)      # seq[позиция] = узел

    def refine(lo, hi, eidx, is_scc):            # eidx: рёбра с ОБОИМИ концами в блоке
        nb = hi - lo
        if nb <= min_block or eidx.size == 0:
            return
        if is_scc:                               # известно, что блок — одна SCC: сразу резать
            return split(lo, hi, eidx)
        ls_pos, lt_pos = pos[src[eidx]] - lo, pos[tgt[eidx]] - lo
        mat = coo_matrix((np.ones(eidx.size, dtype=np.int8), (ls_pos, lt_pos)), shape=(nb, nb))
        n_lab, labels = connected_components(mat, directed=True, connection="strong")
        if n_lab == 1:
            return split(lo, hi, eidx)
        ls, lt = labels[ls_pos], labels[lt_pos]
        cross = ls != lt
        lab_key = np.full(n_lab, nb, dtype=np.int64)
        np.minimum.at(lab_key, labels, np.arange(nb))               # первая позиция каждой SCC
        order_lab = topo_order(n_lab, ls[cross], lt[cross], lab_key)
        lab_rank = np.empty(n_lab, dtype=np.int64); lab_rank[order_lab] = np.arange(n_lab)
        new_local = np.argsort(lab_rank[labels], kind="stable")     # SCC в топо-порядке,
        seq[lo:hi] = seq[lo:hi][new_local]                           # внутри SCC порядок прежний
        pos[seq[lo:hi]] = np.arange(lo, hi)
        sizes = np.bincount(labels, minlength=n_lab)
        starts = lo + np.concatenate([[0], np.cumsum(sizes[order_lab])[:-1]])
        intra = eidx[~cross]
        if intra.size == 0:
            return
        r_of_edge = lab_rank[ls[~cross]]
        o = np.argsort(r_of_edge, kind="stable")
        bounds = np.searchsorted(r_of_edge[o], np.arange(n_lab + 1))
        for r, lab in enumerate(order_lab):                          # рекурсия в каждую SCC
            if sizes[lab] > min_block:
                refine(int(starts[r]), int(starts[r] + sizes[lab]),
                       intra[o][bounds[r]:bounds[r + 1]], True)

    def split(lo, hi, eidx):
        nb = hi - lo
        mid = lo + max(1, min(nb - 1, int(round(nb * split_frac))))
        ps, pt = pos[src[eidx]], pos[tgt[eidx]]
        refine(lo, mid, eidx[(ps < mid) & (pt < mid)], False)
        refine(mid, hi, eidx[(ps >= mid) & (pt >= mid)], False)

    refine(0, n, np.arange(src.shape[0]), False)
    return pos


def alternate_scc_sift(n, src, tgt, w, rank0, cfg, verbose=True):
    rank = rank0.astype(np.int64).copy()
    best_rank, best_score = rank.copy(), score(rank, src, tgt, w)
    fr = cfg["split_fracs"]
    for c in range(cfg["alt_cycles"]):                               # 77
        rank = scc_refine(n, src, tgt, rank, min_block=cfg["min_block"], split_frac=fr[c % len(fr)])
        s1 = score(rank, src, tgt, w)
        if s1 > best_score:
            best_rank, best_score = rank.copy(), s1
        rank, s2 = sift_underrelaxed(n, src, tgt, w, rank, max_sweeps=cfg["alt_sift_sweeps"],   # 2
                                     k_full=cfg["alt_k_full"], alpha=cfg["alt_alpha"], verbose=False)
        if s2 > best_score:
            best_rank, best_score = rank.copy(), s2
    return best_rank, best_score
```

Константы стадии 4: `alt_cycles = 77`, `alt_sift_sweeps = 2`, `alt_k_full = 2`, `alt_alpha = 0.7`,
`min_block = 32`, `split_fracs = (0.5, 0.382, 0.618, 0.25, 0.75)`.

### 6.5 Как объяснить руководителю

«Второй класс ходов — структурный. Непрерывный отрезок позиций — независимая подзадача (лемма).
Внутри отрезка раскладываем подграф на сильно связные компоненты и выкладываем их
топологически: все рёбра между компонентами становятся feedforward, внутри ничего не трогаем —
поэтому ход монотонен по построению, без accept/reject. Компоненту, которая не раскладывается,
режем пополам и рекурсивно продолжаем. Чередуем с коротким sift, потому что классы ходов
взаимно дополняют друг друга. Стадия даёт +0.14 п.п.».

## 7. Сборка конвейера и проверки

```python
def run_h64(n, src, tgt, w, cfg, seed=42, device="cpu"):
    r1 = greedy_fas_order(n, src, tgt, w)                                   # стадия 1
    pos2, s2 = rocket_asym(n, src, tgt, w, positions_from_rank(r1), cfg, seed, device)   # стадия 2
    r2 = np.argsort(np.argsort(pos2, kind="stable"), kind="stable").astype(np.int64)
    r3, s3 = sift_underrelaxed(n, src, tgt, w, r2, max_sweeps=cfg["sift_max_sweeps"],   # стадия 3
                               k_full=cfg["sift_k_full"], alpha=cfg["sift_alpha"])
    r4, s4 = alternate_scc_sift(n, src, tgt, w, r3, cfg)                    # стадия 4
    best = max([(s2, r2), (s3, r3), (s4, r4)], key=lambda t: t[0])          # best-by-oracle
    return best[1], best[0]
```

В продакшне (`H64.run`) дополнительно: бюджет времени передаётся по цепочке (каждая стадия
получает `time_limit` минус уже потраченное), а в `history.attrs` записывается результат каждой
стадии отдельно — именно оттуда таблица в §2. Стадии 5 (парная релокация H52) и 6 (рекламация
дуг H63) в коде есть, но на мухе их бюджет 0: они включены только у мышиного чемпиона.

## 8. Что сказать научному руководителю

### 8.1 Формулировка в одном абзаце

Мы решаем MFAS на коннектоме дрозофилы (136 648 нейронов, 5.66 млн синаптических связей).
Базовый метод — Rocket (Bader et al. 2025): непрерывная релаксация перестановки с сигмоидным
суррогатом и циклическим отжигом резкости. Наш метод H64 — четырёхстадийный конвейер:
жадная FAS-инициализация → Rocket с односторонним асимметричным суррогатом → точный
одноузловой sift с недорелаксацией → рекурсивное SCC-блочное уточнение, чередуемое с sift.
Результат 84.2582% feedforward-веса против 82.87% плато Rocket из статьи и 84.60% у
Rocket + Crane, которому нужен Gurobi и ~20 дней; у нас 20 минут на ноутбучной GPU, без MIP.

### 8.2 Вклад стадий (для слайда)

| стадия | механизм | % после | прирост |
|---|---|---|---|
| greedy-FAS | дискретная эвристика, старт | 68.91 | — |
| Rocket + ASYM | непрерывная релаксация, Adam | 83.24 | +14.32 |
| sift α = 0.7 | точный одноузловой поиск | 84.12 | +0.88 |
| SCC ⇄ sift ×77 | структурный блочный поиск | 84.26 | +0.14 |

Что именно нового относительно статьи: (а) тёплый старт; (б) форма суррогата — единственное

### 8.4 Честные ограничения (руководитель их спросит)

1. **Детерминизм и seed'ы.** Конвейер не потребляет RNG: старт из greedy-FAS, все дискретные
   стадии детерминированы. Само по себе это не гарантирует бит-в-бит повторяемость на CUDA
   (обратный проход gather/scatter использует атомарные float-операции), поэтому аргумент
   эмпирический: seeds 42/123/999/7/31415 дают бит-в-бит одинаковый вектор (σ = 0), и повторный
   прогон в P05 тоже совпал бит-в-бит. Поэтому «среднее ± std по seed'ам» вырождено;
   доверительный интервал считается по протокольному σ базовой линии (0.0189 п.п.).
2. **Чемпион только для мухи.** На microns H64 не измерен: 6 из 8 прогонов усечены защитным
   дедлайном 3450 с (лимит 3600 с минус резерв 150 с) на этой машине, чемпион там остаётся
   H42. На мыши стадия 2 выключена (0 эпох), так что суррогат там вообще не вызывается и мышь
   не является проверкой этого изменения.
3. **Форма суррогата зависит от графа.** (M, T) выбраны на мыши и синтетике; на microns чистый
   Rocket с ASYM хуже сигмоиды, хотя финал чуть лучше. Экстраполировать +0.31 на другие графы
   нельзя.
4. **Механизм не «дальнобойность».** Живой градиент ASYM покрывает 13.1% обратного веса против
   15.7% у сигмоиды. Выигрыш от того, что градиент не тратится на уже правильные рёбра, а не от
   того, что он достаёт дальше.
5. **Железо.** Числа получены на Windows / RTX 4060 Laptop / CUDA 12.8 / torch 2.8.0. На MPS
   (MacBook) траектория Rocket не детерминирована; переносим между машинами только точный
   скорер и вектор позиций.
6. **До референса 0.3565 п.п.** Шесть последующих гипотез убиты при пороге 0.012 п.п.
   (приросты на мухе относительно H64, из `experiments/log.md`): H66 +0.000000 (градиентный
   «толчок» после стека), H73 −0.002271 (другой тай-брейк sift), H79 — тест разброса
   (четыре разных старта сходятся в пределах 0.005879 п.п.), H80 +0.000499 (отжиг принятия),
   H71 +0.005626 (подмножественная бипартиция), H82 +0.000000 (блочный кроссовер). Вывод:
   чемпионский стек «стирает» стартовый бассейн, остаток — не вопрос старта и не вопрос
   мелких ходов.

### 8.5 Что спросят и что ответить

* *Почему не Crane / MIP?* Нужен Gurobi и ~20 дней на 2×A100; наш бюджет 3600 с на ноутбуке.
  Стадия 4 — это дешёвая «структурная» замена: точная на уровне конденсации, эвристическая на
  уровне разреза SCC.
* *Это не переобучение на метрику?* Ни один ход не выбирается по оракулу; оракул только
  принимает/отвергает целый вектор. Формулы gain'а замкнутые и проверены брутфорсом.
* *Насколько стабильно?* Бит-в-бит по seed'ам (см. п. 1), и повторяемо командой из §0 на
  коммите `45d7637`.

## 9. Глоссарий

* **MFAS / FAS** — Maximum Feedforward Arc Set / Feedback Arc Set; одна задача с двух сторон.
* **feedforward-ребро** — `rank[src] < rank[tgt]`; **feedback** — все остальные (включая петли).
* **оракул** — заморожённый точный скорер `score_from_order`; единственный источник чисел.
* **best-by-oracle** — правило «рабочее состояние идёт дальше всегда, а возвращается лучший
  вектор, который оракул когда-либо видел».
* **суррогат** — гладкая замена индикатора `[Δ > 0]` в непрерывной фазе: сигмоида у статьи,
  односторонний `g(z)` у нас.
* **β** — резкость суррогата; циклически отжигается.
* **sift** — одноузловая точная переустановка; **Якоби** — все узлы двигаются одновременно по
  зафиксированному порядку; **недорелаксация (α)** — шаг на долю пути к цели.
* **SCC** — сильно связная компонента; **конденсация** — DAG из SCC.
* **п.п.** — процентный пункт: разница двух процентов.
* **чемпион** — запись в `autoresearch/sota.json`, с которой сравнивается любой новый вариант.
