# Потолок доли прямых связей для коннектома FlyWire: итог

Дата 2026-11-25. Подробный отчёт на английском: `REPORT.md`.

Задача челленджа FlyWire: упорядочить 136 648 нейронов мухи так, чтобы как можно больше синапсов шло вперёд по порядку. Доля веса синапсов на прямых рёбрах называется FF. Наш лучший порядок H64 получен в предыдущей части проекта (оптимизатор, варианты с номерами больше 9). Гипотезы H1 до H9 в этом исследовании нумеруются отдельно.

## Главное

- **Доказано, что ни один порядок нейронов FlyWire не даёт больше 85.3477 % FF.** До исследования была известна только граница 93.2828 %. Она следует из того, что в каждой паре взаимных связей одна сторона обязательно идёт назад.
- Доказательство лежит в файле-сертификате `certs/c45_e.npz`. Его проверяет отдельная программа в целых числах, проверка пройдена (PASS).
- Наш порядок H64 (84.2582 %) отстаёт от потолка на 1.0895 процентного пункта (п. п.), это 456 631 синапс.
- Лучший результат лидерборда (84.8065 %, C. Westfall, 2026-11-08) отстаёт на 0.5411 п. п., это 226 805 синапсов.
- Этим способом (упаковкой циклов) потолок нельзя опустить ниже 85.3455 %. Это доказано и проверено дважды: нашей программой и независимой программой рецензента. Значит, наш потолок почти предельный для этого метода.

## Почему это доказательство

В каждом цикле графа любой порядок обязан пустить хотя бы одно ребро назад. Наберём циклы так, чтобы ни одно ребро не использовалось больше своего веса. Тогда в любом порядке суммарный вес обратных рёбер не меньше суммы весов этих циклов. Мы набрали 6.7 млн циклов с дробными весами на сумму 6 141 103 синапса. Значит, назад уходит минимум столько, а вперёд остаётся максимум 85.3477 %.

Проверка не доверяет солверам. Программа проверки сама читает рёбра графа, для каждого цикла проверяет, что он настоящий, а для каждого ребра, что его вес не превышен. Всё считается в целых числах. Программу проверки писали отдельно от кода, который ищет оценки. Независимый рецензент атаковал её 22 поддельными сертификатами, и ни один неверный сертификат не прошёл.

|---|---|---|

| жадная упаковка 2- и 3-циклов | 89.0231 | нет (вариант с сертификатом 89.1292) |
| маршрутизация по порядку H64 | 86.0569 | есть |
| генерация столбцов, короткие циклы | 85.9467 | есть |

## Как получили (коротко)

1. Посчитали 2- и 3-циклы. Жадная упаковка упирается примерно в 89 %.
2. Брали обратные рёбра порядка H64 и для каждого искали путь вперёд по порядку, который замыкает цикл. Так нашлись полезные циклы любой длины, не только короткие. Потолок 86.06 %.
3. Решили линейную релаксацию по циклам (LP), добавляя нужные циклы порциями (генерация столбцов). Потолок 85.95 %, потом 85.35 %.
4. Отдельно доказали верхнюю оценку значения LP, то есть предел для любой упаковки циклов. Сначала получили 85.2248 %, потом довели до 85.3455 %. Интервал между нижней и верхней оценкой LP теперь 931 синапс.

Сам потолок 85.3477 % от верхней оценки LP не зависит.

## Что это значит, а что нет

- Доказано: лучший результат лидерборда не дальше 0.54 п. п. от оптимума, наш порядок не дальше 1.09 п. п.
- Неизвестно, где оптимум между 84.8065 % и 85.3477 %. Разница складывается из двух частей: насколько плохи порядки и насколько LP занижает оптимум. Разделить их упаковка циклов не может в принципе.
- Мы проверили LP на маленьких графах, где оптимум можно найти точно (MILP). Это мышиный коннектом из 148 нейронов, 182 фрагмента графа мухи и 71 окно, то есть блок от 300 до 3000 соседних нейронов в порядке H64. На мыши LP совпал с точным оптимумом (93.202194 %). На фрагментах мухи LP почти равен оптимуму. На окнах LP в среднем ниже оптимума на 0.016 % (относительно). На 34 окнах по 3000 нейронов H64 выше оптимума окна на 1.3 % (по разным группам окон от 1.3 до 3.3 %).
- Догадка: скорее всего, большая часть оставшихся от 0.54 до 1.09 п. п. приходится на неоптимальность порядков, а не на слабость LP. Это не проверено для длинных циклов через весь граф, а на них приходится 84 % обратного веса H64.

## Что это значит для нашей оптимизации

- Точная переоптимизация окон из 3000 соседних позиций даст мало, от 14 до 22 тыс. синапсов (оценка). До лидерборда нам не хватает 229 826.
- Наш избыток в основном в дальних связях, которые окна не видят. Улучшать надо глобальную структуру порядка, а не локальные куски.
- Побочный результат: округление LP по окнам дало порядок 84.2737 %, на 6 490 синапсов лучше H64. Это один проход, порядок не сохранён.
- Мышь: наш лучший порядок для мыши (H63) на 0.0268 п. п. ниже точного (MILP) оптимума.

## Ограничения

- Упаковкой циклов ниже 85.3455 % не опуститься. Нужна более сильная релаксация на всём графе, а её мы в полном масштабе не пробовали.
- Числа калибровки получены солверами с плавающей точкой. В целых числах проверены только сертификаты и верхние оценки LP.
- Сертификат c45_e весит 110 МБ и в git не лежит. Пересобрать его можно командами из `results/M_CLOSE.md`, но для этого нужны промежуточные файлы из временной рабочей папки сессии. Если они потеряны, цепочку придётся пересчитывать с начала, а первые шаги (метод P) записаны только в логах, без готовых команд.

## Для научного сообщества (по нашему поиску литературы)

- Похоже, это первая доказанная граница для этого публичного челленджа. Опубликованных оценок мы не нашли. Есть репозиторий `mdindoost/mfascert` с похожей идеей, но 2026-11-25 он отдавал 404, и проверить его числа нельзя.
- Результат может проверить любой: нужен файл сертификата и небольшая программа проверки без солвера.
- Научный вывод: LP по циклам почти точен на всех кусках коннектома, которые удалось решить точно. Держится ли это на всём графе, открытый вопрос.

## Следующие шаги (предложения)

1. Решить, как хранить c45_e (110 МБ): внешний архив (например, GitHub release или LFS) или пересборка по командам.
2. Чтобы понять, где оптимум: попробовать более сильную релаксацию, например неравенства задачи линейного упорядочивания (LOP), на плотных центральных кусках, где LP уже показывал разрыв.
3. Для оптимизации: искать улучшения порядка в дальних связях и использовать двойственные длины LP как подсказку.
4. Перед любой публикацией перепроверить mfascert и лидерборд.
